# 申论词库

申论备考用的静态网页：查资料、做真题、分项练习、复习。不需要后端，不联网也能用，可以直接放到 GitHub Pages。手机、平板、电脑都能用，记录只存在本机浏览器里。

## 有什么

**资料**
- 规范词 420 条（21 期，按场景筛选）
- 对策 70 条模板，配 72 条问题表述，两边可以互相跳转；选几条对策能合成一段
- 案例 560 条（7 章 56 个小节）
- 公文 24 种：结构、例文、交卷前检查项

**真题**
- 253 套国考和省考申论卷，按省份、年份挑卷
- 电脑上左边材料、右边作答；手机上「材料 / 作答」两页切换，切换条始终吸在顶部，读材料时题目钉在上面
- 材料可以四色标注：点一句标一句，或划选到字；同色再点取消
- 作答用作文方格纸，每格一字，点哪格从哪格写。自动识别题目字数上下限，超出的格子标红
- 输入即自动保存；180 分钟倒计时，每套卷单独计时
- 提交后本机按规则打分：要点覆盖、结构逻辑、规范表达、格式卷面、论证深度五项，给出先改哪几处。分数只是参考
- 参考答案来自开源题库，标明「已核对 / 基本吻合 / 仅供参考」，不是官方答案。匹配脚本见 `tools/answers/`
- 答案面板把三样东西分开：**参考答案**（真实答案，分条列点 / 公文版式 / 作文范文按各自的样子排）、
  **参考答案说明**（为什么这么分条、踩的是哪几个得分点）、**其他来源的答案**（同一道题的其他版本，折叠对照）。
  说明和范文点评不会混进答案正文里：题库把这几种写法都试过了——说明接在答案末尾、
  夹在段落中间、和「参考答案二」挤在同一段、整条「答案」其实只是审题思路——页面都会拆出来单独成块，
  没有成稿答案的题会直接标明「只有思路说明」

**练习**
- 小题 327 道：概括、分析、对策，写完逐条对要点
- 大作文 119 篇：只写标题、三条分论点和收尾句，边写边检查结构
- 标题分论点 8 组：限时立骨架
- 素材：金句、案例、规范表述、替换词、行文骨架，可搜索和收藏
- 记录：得分率、连续天数、按得分排的复习日期

**复习**
- 待复习、已掌握、收藏、笔记
- 一组 10 题的快练，自评结果会记到掌握状态里

## 界面设计

整体是「纸与墨」：暖白底、墨色字，朱砂色只用在品牌标记、超限和危险操作上。图标用 [Lucide](https://lucide.dev)（ISC 许可），不用 emoji。

按人怎么用来定的几条规矩：

- **拇指够得着**：手机上主导航在底部 5 个标签；详情、选卷、批改报告都从底部滑出，可以下拉关闭；主要按钮放在屏幕下半部
- **点得准**：触屏上所有可点的地方不小于 44 px；输入框字号不小于 16 px，iOS 不会自动放大页面
- **读得久**：材料和例文用宋体，行高 1.9 左右，可在设置里换黑体；字号三档；方格纸在手机上宁可每行少几格，也保证字不小于 12 px
- **不打断**：返回键和 Esc 先关最上面一层，再退回上一页；切换页面记住滚动位置；做题时收起无关导航
- **看得清**：正文对比度达到 WCAG AA；深色模式跟随系统，也可手动切换；支持「减少动画」
- **不丢东西**：输入即保存，切后台时立刻落盘；清空、重置这类操作先确认

断点：

| 宽度 | 布局 |
| --- | --- |
| ≥ 1024 | 左侧栏 + 内容，详情在右侧并排 |
| ≤ 1023 | 侧栏收起，改用底部标签栏；详情变成底部弹层 |
| ≤ 760 | 单栏；搜索点开后全屏；真题分「材料 / 作答」两页；列表改为分组行 |
| ≤ 359 | 压缩间距 |
| 横屏且高度 ≤ 480 | 底部标签栏压矮、只留图标，把高度留给内容 |

适配了 iOS 安全区（刘海、底部横条）、`100dvh`、软键盘弹出、打印样式。

键盘：`/` 或 `Ctrl/⌘ K` 搜索，`1`–`9` 切换页面，`Esc` 关闭弹层。

## 文件

```
index.html              页面结构
manifest.webmanifest    添加到主屏幕用
assets/
  app.css               设计令牌和全部通用样式
  app.js                外壳、资料、复习、设置、搜索、真题作答与批改
  icons.js              图标（Lucide 精灵图）
  icon.svg / icon-*.png 应用图标
data/
  library.js            规范词、对策、案例
  formats.js            公文文种（生成的，别手改）
  problems.js           问题表述（生成的，别手改）
exams/
  index.js              真题目录
  gk.js prov1.js prov2.js          试卷，按组懒加载
  answers-*.js answers-meta.js     参考答案，按组懒加载
  kk.js kk.css          标注笔和方格纸，真题和练习共用
  lab/                  练习模块（数据、逻辑、样式）
tools/
  library/              生成 formats.js 和 problems.js
  answers/              匹配参考答案
  stamp_assets.py       给 index.html 里的 css / js 地址加内容指纹（上线前跑）
```

改样式先看 `assets/app.css` 开头的变量：颜色、字号阶梯（`--t-xs` 到 `--t-3xl`）、圆角、间距都在那里，`exams/kk.css` 和 `exams/lab/lab.css` 只引用这些变量。

## 本地运行

直接双击 `index.html`；或者在当前目录执行：

```bash
python3 -m http.server 4173
```

然后打开 http://localhost:4173 。

## 部署到 GitHub Pages

1. 把整个目录推到 GitHub 仓库（需要 `index.html`、`manifest.webmanifest`、`assets/`、`data/`、`exams/`、`.nojekyll`）。
2. Settings → Pages → Deploy from a branch → main / (root) → Save。
3. 访问 `https://你的用户名.github.io/仓库名/`。

**上线前**：只要改过 css 或 js，提交之前跑一次

```
python3 tools/stamp_assets.py
```

它会把 `index.html` 里的引用改成 `assets/app.js?v=1a2b3c4d` 这样带内容指纹的地址。GitHub Pages 让浏览器把每个文件各自缓存 10 分钟，不带指纹的话，上线或回滚后的这 10 分钟里，浏览器可能用新的页面去配缓存里旧的脚本和样式，页面会直接报错。带上指纹后文件一变地址就变，不会混用。`python3 tools/stamp_assets.py --check` 可以只检查不修改。

回滚也是一次上线：用 `git revert` 撤销对应的合并提交，再跑一次上面的命令。

## 学习记录

收藏、掌握状态、标注、作答、批改结果和笔记都只存在当前浏览器的 localStorage 里。清理浏览器数据、换设备或换浏览器都会丢失，建议隔段时间到「设置」里导出一次备份，换设备时再导入。
